3. New findings
Blocker
N-01: Android OS auto-backup is on
• Evidence:
• android/app/src/main/AndroidManifest.xml has no android:allowBackup="false"
", no
android: fullBackupContent and no android: dataExtractionRules.
• On Android 6 and later, the default is to copy app data to Google Drive. On Android 12 and later, the default also allows a transfer from one device to another.
• Effect:
• When T07 creates the database, the encrypted file and the shared preferences can leave the phone.
• This breaks AGENTS 2.1, "no cloud/device backup or sync". It is the Android form of PF-01.
• Change:
• Set android:allowBackup="false" and android:fullBackupContent="false"
• Add a data_extraction_rules. xml that excludes every domain for both cloud-backup and device-transfer .
• Add a T11 test that reads the merged manifest.
• Record the result in DECISIONS as PF-01-ANDROID.
• Also check that the release manifest has no INTERNET permission until the price gateway task. Now only the debug and profile manifests have it, which is correct.

N-03: The Done/Default commit does not follow the framework contract
• Evidence:
• widget-framework.md lines 99-100 say that Default "returns the surface to inheritance", and that Done stamps the base_layout_version.
• editor. dart done) always returns a full LayoutCommit with a copy of the sections, even when isDefaultScope is true.
• No orchestrator calls LayoutRepository.clear() .
• InMemoryLayoutRepository.save
discards newInThisVersion.
• Effect: after Default and then Done, a row is stored, so a later release default no longer reaches that user (W-J).
• Change:
• Return a sealed result from done() : InheritDefault(surfaceKey) or SaveLayout(commit).
• Map InheritDefault to clear) .
• Store or remove newInThisVersion deliberately.
• Add W-J tests: Default then Done stores no row, and stamp-only Done writes once.
N-04: The editor's "new in this version" set is wrong in three cases
• Evidence: editor.dart:
• insert() adds the key to _newKeys . A move between sections ( take then insert ) therefore marks a moved widget as "new".
• hide() does not remove the key from _newKeys, so a widget that is added and then hidden is still reported.
• done () also counts each key that is not in the default as new. A widget that the user added in an earlier release becomes "new" again at each Done.
• Effect: the "New in this version" list (widget-framework 96-100) shows the wrong widgets.
• Change:
• Calculate the set only at upgrade time: keys in the installed bundle that are not in the bundle of baseLayoutVersion.
• Do not calculate it from the session edits.
• Remove _newKeys from hide and insert, or drop it.
• Add tests for move, add then hide, and an earlier-release addition.


N-05: Two value-state models
• Evidence:
• read_store.dart MetricState {loading, value, missing, noneRecorded, notAvailable} with Object? value.
• value_presentation.dart ValueState {real, estimated, expected, noneRecorded, missing, oldPrice}.
• W3.4 needs Loading, Missing, None recorded, Estimated, Hidden and Not available for each widget.
• Effect:
• Each widget must map one enum to the other by hand.
• Estimated, Expected and Old price are lost in the read store.
• notAvailable and loading have no presentation.
• This is the drift that CR-03 removed from the components.
• Change:
• Make MetricValue carry a ValueSpec, or a typed MetricValue<T> with a ValueSpec mapping, plus loading and notAvailable(reason) .
• Add ValueSpec.notAvailable(label) and a loading presentation to formatValuestate.
• Remove Object? value .
